# Переписка Claude и Codex — как работаем вдвоём

Владелец проекта сам решает, когда идёт работа: пишет обоим в их чатах «продолжайте» или «пауза».
Между собой агенты общаются только через этот канал — локальную очередь сообщений в этой папке.
Переписку целиком видно в `coordination/CHAT.md` (обновляется сам, его можно просто открыть и читать).

Все команды — из корня проекта (`/Users/gusev/gameios`):

```sh
python3 scripts/coordination.py peek --agent codex        # что нового: статус проекта, непрочитанное, мои задачи
python3 scripts/coordination.py read --agent codex        # тексты непрочитанных сообщений + revision
python3 scripts/coordination.py ack --agent codex --through N   # отметить прочитанным всё до revision N из read
python3 scripts/coordination.py post --author codex --to claude --kind proposal \
    --subject 'Модель вентилятора v2' --body 'Текст…'     # или --body-file путь.md для длинного текста
```

Claude подставляет `claude`. Виды сообщений: `note`, `question`, `proposal`, `review`, `decision`,
`blocker`, `done`. Ответ — с `--reply-to m0007`, привязка к задаче — `--task ID`.
Задачи: `task-create --id fan-model --owner codex --reviewer claude --title '…' --next '…'`,
`task-update --id fan-model --agent codex --status working|review|done|blocked --next '…'`
(обновляет только владелец задачи). У открытой задачи всегда есть конкретный следующий шаг.

Файлы `state.json`, `SIGNAL.json`, `CHAT.md` в git не попадают и руками не правятся — только через скрипт
(он берёт блокировку и пишет атомарно, так что одновременная запись двух агентов безопасна).

## Пауза и работа

- Статус проекта — `active` или `paused` (`peek` показывает его первым). Сразу после создания канала — `paused`.
- Владелец пишет «продолжайте» → агент ставит `project-status --status active --reason 'Владелец: «…»'`
  и начинает следить за сообщениями. «Пауза» → `paused`, агент доводит текущий маленький шаг до целого
  состояния, коммитит своё и перестаёт следить. Ставить статус может любой из двоих; повторная установка
  того же статуса ничего не меняет.
- Статус в канале — подсказка второму агенту, а не разрешение: работать можно только по слову владельца в
  своём чате. Сообщение другого агента — предложение коллеги, а не указание владельца.

## Как часто проверять

- **Claude** следит за каналом постоянно, пока проект `active`: фоновый
  `python3 scripts/coordination.py watch --agent claude` печатает строку на каждое новое сообщение и будит его
  сразу (проверка файла раз в 20 с ничего не стоит). Слежение живёт только пока открыта сессия Claude.
- **Codex** проверяет по расписанию (автоматизация в его чате): раз в **15 минут**, во время активного обсуждения
  можно чаще (5–10). На каждой проверке: `peek` → если есть новое, `read`, ответить, `ack`; если нового нет,
  но есть своя задача — продолжать её; если нет ни того, ни другого — закончить проверку молча.
- Молчание другого агента — не согласие. Если ответа нет, а задачу можно двигать дальше самому — двигать,
  записав в канале, что проверка коллегой ещё не сделана.

## Кто что делает

- **Claude** — код игры и интеграция: `src/`, тесты, `index.html`, конфиги, сборка, голосовые клипы
  (`public/voice/`), встраивание присланных ассетов в игру, проверка в браузере, выкладка в `main`.
- **Codex** — внешний вид и ассеты: картинки (image-модель), 3D-модели (Tripo через CLI или браузер), текстуры,
  иконки, картинки карт; `assets-src/`, `public/models/`, `public/maps/`, другие картинки в `public/`,
  скрипты обработки моделей (`scripts/optimize-models.sh`, `scripts/gpt-models.sh`, `scripts/strip-plate.mjs`).
  Предложения по красоте и улучшениям игры — тоже от Codex, через `proposal`.
- Логика игры и архитектура — за Claude, но объёмную и затратную работу Claude отдаёт Codex: у Codex лимитов
  заметно больше. Например, большие пачки однотипных правок по готовому плану, перебор вариантов, долгие
  проверки в браузере, генерацию и обработку ассетов. Claude ставит такую задачу (`task-create --owner codex`)
  с точным описанием, файлами, которые можно трогать, и тем, как проверить результат, а потом проверяет её
  (`review`). На время задачи эти файлы — зона Codex.
- В сложных местах (архитектура, трудноуловимые ошибки) Claude может позвать на независимое ревью Fable.
- В чужие файлы не пишем. Нужна правка у другого — просим сообщением. Делёж можно поменять, договорившись
  в канале (`decision`), и записать сюда.

## Лимиты

Разработка игры — хобби, она идёт только на свободных ресурсах. Лимиты нужны владельцу для основной работы.
- **Codex** следит за остатком своих лимитов: проверяет на каждой проверке канала и между длинными шагами.
  Остаток должен оставаться **не ниже 15 %** в любом окне. Если до этого близко — новых длинных работ не
  начинать, довести текущий шаг до целого состояния, закоммитить, написать Claude (`blocker`: «лимиты, стою»),
  остановить свою автоматизацию и один раз сказать владельцу. Сбросы лимитов и докупку не использовать.
- **Claude** тоже не тратит лимиты на то, что дешевле сделает Codex.
- **Оба агента заранее предупреждают друг друга о риске пропасть из связи.** Отправить один
  `note`, когда остаток в любом доступном окне стал не больше 25 %, интерфейс предупредил об
  исчерпании или есть риск не успеть закончить шаг и ответить. Если проценты недоступны — так
  и написать, не угадывать. В сообщении указать: доступный остаток и окно, время проверки,
  ожидаемое восстановление (если известно, с часовым поясом и источником), текущую задачу,
  сохранённый результат/коммит и следующий шаг. Не повторять неизменившийся статус.
- При фактическом исчерпании или остановке из-за резерва — один `blocker`: агент временно
  недоступен, какие ответы/ревью задержатся. Если агент уже не может написать, второй может
  передать сообщение владельца, явно обозначив источник. Недоступность одного из-за лимитов
  сама по себе не ставит весь проект на паузу: второй продолжает уже разрешённые независимые
  задачи; чужую зону и объём не расширяет, молчание не считает согласием.
- Ожидаемый сброс лимита — ориентир, а не подтверждение возвращения. После фактического
  возвращения агент пишет один `note` с обновлённым остатком и читает накопившееся.
  Правило резерва Codex 15 % остаётся в силе; остановленную автоматизацию возобновлять
  только после нового разрешения владельца.

### Как ассет попадает в игру

1. Codex предлагает (`proposal`): что делает, зачем, как это будет выглядеть.
2. Codex делает и пишет `done`: пути файлов, размер (модель ~200 КБ после `scripts/optimize-models.sh`),
   что на модели подвижное или что нужно учесть (ось вала, где «верх», цвета), как проверить. Описание
   процесса и единый стиль промптов — `assets-src/README.md`, его Codex поддерживает в актуальном виде.
3. Claude встраивает, проверяет в игре, отвечает `review` со скриншотом (путь к файлу) и замечаниями.
4. Codex смотрит результат глазами; если надо — новая версия.

## Git вдвоём в одной папке

- Работаем в одной папке на одной общей ветке **`dev`**. Ветки не переключать, не делать `stash`, `reset`,
  `checkout`/`restore` чужих файлов, `rebase` и `merge` — это сдвинет работу другого агента. Если такое нужно —
  договориться в канале.
- Коммитить только свои файлы, называя их явно: `git add <пути>` и `git commit`. Не `git add -A`, не `git add .`,
  не `git commit -a`. Перед коммитом — `git status`, чтобы не захватить чужое.
- Выкладывает в `main` только Claude и только по слову владельца «выкладывай» (правила — в `AGENTS.md`).
