# Контрастная плитка C

Для замечания Claude m0400: исходная paving A теряет сетку в общем виде города. Новый `paving-main-c.webp` сохраняет тёплый камень, но увеличивает квадрат с1до2ед и усиливает швы. A/B и файлы исполнителя не изменены. C:2048²,202 658байт, непрозрачный, покрытие8×8ед. Нативный PNG1254² увеличен Lanczos1,633× в sRGB/WebP85.

Два встроенных вызова imagegen: исходный вариант и исправление фазы повторения. У v1 края обрезали швы, при повторе образовывалась двойная ширина квадрата. V2 имеет четыре шва и половинки плиток по краям; v1 сохранён в iterations/. Полные промпты в prompts.json, SHA/метрики в manifest.json. Только технический resize/encode; никаких зеркал, шовного blend или рисования кодом.

Проверены3×3 повтор,64/128px на8ед рядом с A, крупный стык и общий вид газона с новым бордюром. C читается отчётливо даже в390px preview. Средняя разница противоположных краёв4,71RGB слева/справа и4,59 сверху/снизу; сетка визуально непрерывная, фактура не попиксельно бесшовная. QA/8 нативных JPEG и воспроизводимая страница находятся в ../edges-water/ (совместный проход390×844 и1024×768,без ошибок и горизонтального переполнения).

`kit.json` включает кандидата C для интеграционного сравнения. **kitPieces возвращает A первым независимо от порядка kit.json**. Для включения C Claude должен явно выбрать его в src/city.ts; основной чат не менял src. Текущий runtime tint #e8dcd4 может дополнительно повлиять на контраст, нужен игровой кадр. Это приёмка ассета, не подтверждение игрового вида/iPad/FPS/PWA.

Повторить упаковку: `node assets-src/design-pass/kit/city/paving-contrast/build.mjs`. Все картинки сделаны встроенным image_gen, CLI/API не применялись.
