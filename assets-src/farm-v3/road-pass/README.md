## Побайтная сохранность

В каждом из двух JSON меняются **ровно 19 числовых токенов width**. `json_spans.py` находит значения по полному пути JSON и заменяет только соответствующие токены, не сериализуя весь документ заново. `verify.py` маскирует только эти 19 значений и сравнивает все остальные байты. Это проверяет в том числе формат чисел, пробелы, порядок ключей, все 686 позиций, группы, точки дорог и метаданные.

В сгенерированном TypeScript также меняются ровно 19 числовых токенов width внутри PATHS; заголовок, DECOR и остальные экспорты побайтно совпадают с baseline. Независимый `verify-runtime.mjs` загружает каждый реальный экспорт TypeScript после удаления типов и сверяет с соответствующим JSON, до и после изменения.

Восемь исходников закреплены в `baseline/`, их SHA-256 — `baseline-manifest.json`. Исходный build-decor.py не исправлялся. Сначала подтверждена его побайтная стабильность на baseline, затем создан кандидат через **штатный `--from-authoring` в собственной `.snapshot/`**. Экспортёр читает дороги из layout, поэтому ширины синхронно изменены и в author.paths, и в layout.PATHS. Копии моделей для штатных проверок извлечены из того же закреплённого коммита; их хеши — `model-manifest.json`.

## Связность и зазоры

Точки и порядок дорог совпадают побайтно. Независимый анализ точных рациональных координат учитывает пересечения, T-стыки и совпадающие коллинеарные участки: **19 маршрутов, 43 отрезка, 62 вхождения точек, 20 связей между маршрутами, одна компонента**. Граф до и после совпадает полностью. Это дополнительно подтверждено штатным check-farm-decor.

Доказательство неуменьшения зазоров не зависит от формы декора: при неизменной осевой линии C дорожный коридор с круглыми окончаниями и стыками равен C, расширенной диском радиуса width/2. Новый радиус меньше старого, поэтому новый коридор целиком содержится в старом. Это сохраняется для объединения всех дорог. Следовательно, расстояние до любого неизменного препятствия, в том числе полного силуэта дерева или здания, уменьшиться не может.

Для метрики `расстояние до осевой линии − width/2` прирост каждого из 19 коридоров составляет **0,2–0,4** единицы. Численная сверка выполнена для **789 объектов измерения**: всех 686 центров DECOR, центров заданий/столбов/игрушек и 64 полных отрезков оград. Минимальный прирост 0,2 с погрешностью чисел с плавающей точкой. Минимальный зазор ограда–дорога: **0,39844056 → 0,63700000**.

Универсальное доказательство относится и к полным неизменным габаритам; численная таблица центров не подменяет габариты радиусами. С учётом неизменной дорожки лисы общий зазор также не уменьшается, но гарантировать прирост 0,2 для всей сети уже нельзя: ближайшей может остаться именно эта дорожка.

В неизменённом ground.ts подтверждены круглые окончания/стыки и все восемь painted-слоёв маски: `w + 0.6*k`, `w`, `max(0.2, w-0.8)`. Каждый слой только сужается, центральный остаётся положительной ширины. Это аналитическая проверка формы штриха. Пиксели антиалиасинга, растушёвка, материалы и читаемость в игре проверяются основным чатом. Существующая функция onLane также получает новые ширины по прежней логике.

## Проверки и воспроизведение

- `verification.json`: **pass**, изменения только widths, сохранены 686 объектов, граф совпадает, зазоры не уменьшаются.
- `validation-before.json` и `validation-after.json`: штатный check-farm-decor прошёл в снимке; 19 дорог, 64 ограды, 18 растений поля, 36 растений грядок.
- `clearance-audit.json`: все 789 измерений до/после.
- `build-log.json`: штатный экспорт и результаты валидатора.

Из корня репозитория:

```sh
python3 assets-src/farm-v3/road-pass/build.py
python3 assets-src/farm-v3/road-pass/verify.py
```

Обе команды пишут только внутри road-pass. `.snapshot/` и Python cache исключены из Git. Для воспроизведения нужны этот репозиторий с baseline-коммитом, Python и текущий Node с stripTypeScriptTypes; браузер и npm-команды не нужны.

При интеграции проверить соответствие имён и значений before, затем применить patch к актуальным author.paths/layout.PATHS и использовать `build-decor.py --from-authoring`. Если после baseline появились другие правки, не заменять общий авторинг целиком старым candidate. Старый default-генератор не запускать.

Браузер, npm tests/typecheck, новые модели/текстуры и изменения ground.ts/farm.ts не выполнялись по разделению работы. Этот отчёт не утверждает отсутствие всех прежних пересечений дорог с объектами: доказано, что сужение их не ухудшает. Реальная before/after QA и итоговая интеграция остаются основному чату.
