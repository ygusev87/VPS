## Уточнение проверки InstancedMesh — m0207

Claude подтвердил положение двери и бабушки в игре, но обнаружил вывернутые
грани зеркального узла при отрисовке декора. Обычный Mesh в первоначальном
стенде скрывал этот дефект. В игре исправлено Claude в `7f4f986`: `patched()`
разворачивает обход треугольников зеркальных узлов. Сам GLB не менялся.

Стенд теперь импортирует **реальный `patched()` из src/storymap.ts**, дом рисуется
одним InstancedMesh. Повторно проверены1180/390px, игровой угол и три четверти:
стены/крыша видны, дверь и бабушка на месте. Снимки `qa/grandma-house-instanced-*`.
Ревью всей задачи с корзиной/лифтом и iPad это не заменяет.

IAB записал один MutationObserver.observe TypeError без URL в20:40:06 UTC,
25.10.2026. В исходниках src такого вызова нет; происхождение не установлено.
Это уже встречавшийся диагностический вопрос, а не подтверждённая ошибка модели.
Прежнее утверждение о чистом журнале относилось к старому запуску стенда.

## Файл и подготовка

`candidate/grandma-house.glb`: **141352 байта (138.0KiB),7068 треугольников**, один
материал, цвет512×512 WebP, Meshopt. Статический корпус без балкона и персонажей.
Сырые1059680 байт сохранены вне git в
`assets-src/raw/city-v2-2026-10-26/grandma-house.glb`; нормализованный промежуточный
GLB891908 байт. `mobile-report.json` сравнивает именно промежуточный и конечный
файлы. Число треугольников при оптимизации сохранено. Оценка памяти цветной
текстуры RGBA8+mips21.33→1.33MiB — расчёт по размерам, не измерение GPU.

Нативная боковая дверь смотрит+X, передний фасад−Z. `model-spec.json` задаёт
поворот90° и отражениеX; в сочетании с игровым rotateY−π/2 это отражает нативныйZ.
Дверь остаётся на игровой стене+X, её центр оказывается около нужного z+0.25.
При fit.width6.2 файл уже ориентирован под существующий вызов `model()`;
не применять нормализацию второй раз. На задней стороне генератор повторил
первый фасад с дверью; отдельной балконной геометрии в корпусе нет.

Воспроизведение из корня проекта:

```sh
node scripts/prepare-farm-models.mjs assets-src/raw/city-v2-2026-10-26 /tmp/grandma-house-canonical-20261026 assets-src/city-v2/grandma-house-3d/model-spec.json grandma-house
node scripts/optimize-mobile-models.mjs --input /tmp/grandma-house-canonical-20261026 --output assets-src/city-v2/grandma-house-3d/candidate --report assets-src/city-v2/grandma-house-3d/mobile-report.json grandma-house
node assets-src/city-v2/grandma-house-3d/measure-fit.mjs
```

## Измеренный конфликт стыка

При текущем fit `{width:6.2, rotateY:-Math.PI/2}`, центре(-44,-27) и основанииY0:

| Параметр | Значение |
| --- | --- |
| Полный X/Y/Z, включая крышу | 6.2 / 7.7331 / 4.7594 |
| Первая бирюзовая граница боковой двери при z+0.25 | y2.225 |
| Настил | y1.95; внутренний край localX3.1 |
| Дверь выше настила | ≈0.275 |
| Стена на высоте настила | localX2.8072 |
| Зазор от стены до внутреннего края настила | ≈0.2928 |

Метод: raycast декодированных треугольников с+X, UV и цвет атласа в пяти сечениях
z−0.1…+0.55. Первая бирюзовая граница — **оценка видимого низа двери**, не точное
семантическое ребро порога; погрешность порядка0.02–0.05 игровых единиц.
Измерения и ограничения — `fit-measurements.json`.

Предложение Claude: сохранить width6.2 и все игровые якоря, снизить только
высоту корпуса множителем0.8764 (высота≈6.777), продлить настил к стене на0.30.
Настил шириной1.9 с localX−0.15 сохраняет внешний край; перила, стойки, бабушка,
лифт и BALCONY остаются на своих местах. Контакт с домом получает небольшой
нахлёст≈0.03. Это **предложение**, в файле модели/игре оно не запечено.

Альтернатива — width≈6.786 и Y-множитель≈0.8007, но увеличенный footprint требует
повторной проверки соседей. Первый вариант сохраняет площадь корпуса.
