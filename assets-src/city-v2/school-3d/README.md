## Вход не совпадает с целью детей

Обычный fit.width9/rotateY−π/2 даёт полный габарит **9×6.1231×4.9256**.
При центре(11,−30) голубая поверхность центральной двери в сечении y0.6
имеет localz2.004 вместо нужных4.5: до фиксированного SCHOOL_DOOR(11,−25.5)
остаётся2.496. Нижние пробы y0.05…1.5 подтверждают ту же поверхность;
самая нижняя центральная поверхность найдена при y0.01, подиума не видно.

**Предпочтительное предложение:** сдвинуть только визуальный корпус на+2.496Z,
то есть центр(11,−27.504), сохранив исходные пропорции и все точки задания.
Это требует изменения ранее согласованного центра здания; пока выполнено
только в стенде и измерительном скрипте, решение за Claude.

**Альтернатива:** глубина×2.2455 при прежнем центре. Полная глубина11.0605,
боковые окна и крыша сильно вытягиваются; визуально хуже. В GLB не применено.
Сравнение — `fit-review.html`, переключатель подгонки.

## Проверка предложенного сдвига

`offset-preview-measurements.json`:

- габариты модели прежние; дверь localz4.5 относительно исходного центра(11,−30);
- минимум расстояния от ПОЛНОЙ проекции bbox к горизонтальному лучу3.391,
  к вертикальному9.0277. Включены крыша, карнизы и колонны;
- лучи по центрам трёх подходов детей при y0.6 достигают фасада только в конце;
- до северного края доски7.5332, корпус остаётся внутри доски.

Это консервативная геометрия bbox/центральных лучей, не запуск traceBeam,
не swept collision фигур и не проверка всей карты/озеленения. Капсулы в стенде
служат контрольными объёмами высотой1.15, не заменяют настоящих детей.
При100% их центры совпадают с плоскостью двери. При интеграции отдельно проверить
первого ребёнка, который остаётся видимым: если нужна дистанция от закрытой двери,
можно выбрать чуть меньший сдвиг корпуса (например+2.246 даёт отступ0.25);
это тоже решение размещения, а не перенос точки SCHOOL_DOOR.
